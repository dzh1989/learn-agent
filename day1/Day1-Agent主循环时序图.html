决策 / 执行

模型只发意图，代码才执行

第 3 步返回的 tool_calls 是一段 JSON。模型没有网络、没有文件权限，它只能"请求"。所以安全校验、超时重试、幂等全部必须落在执行层。

无状态

每一轮都是全量重放

第 8 步把 4 条消息整体再发一次。服务端不记得上一轮——所谓的"对话记忆"，就是你手里这个不断 append 的数组。

契约

tool_call_id 是强绑定

工具结果必须带回对应的 id。少了它，模型无法把"结果"和"请求"配对，并行调用时会直接串味——这是最常见的低级 bug。

面试一句话："Agent 循环本质是一个无状态的 while 循环：每轮把完整的 messages 和 tools schema 发给模型，模型只返回意图（tool_calls），执行发生在我的代码里，结果以 role=tool 回灌，直到模型不再请求工具。" 再补一句加分："因为每一轮都全量重放，所以成本随轮次增长——这也是 prompt caching 和上下文压缩的价值所在。"
