# 主项目：AI SaaS 竞品研究 Agent

> 本目录是整套课程的**贯穿项目（Capstone）**，能力随课程从雏形一路长到可评测、可部署的系统。
> 各节课的**通用能力代码**在仓库根目录的 `dayNN-*` 中；本项目是它们组合后的**真实应用**。

## 这是什么

用户输入若干 SaaS 产品名 + 研究目标，Agent 辅助完成：

```
资料收集 → 整理归类 → 横向对比 → 报告生成
```

例如输入「Notion / Coda / Craft，对比它们的 AI 写作能力」，Agent 自动搜集公开资料、做结构化对比、产出一份可阅读的研究报告。

## 为什么选它

- **真实需求**：竞品研究是高频、可演示、可评测的任务，适合做作品集。
- **覆盖全能力栈**：Loop / 工具 / MCP / RAG / Memory / 编排 / 评测 / 部署，课程里学的每一项都能挂上来。
- **难度线性增长**：每学一个能力就增强一点，不会出现「前面学的用不上」的断层。

## 三阶段演进（与课程对齐）

### Stage 1 · 初级雏形（第 5–6 节）
- 手写 Agent Loop：跑通「观察 → 思考 → 行动 → 调用工具 → 再观察」的循环。
- 首个 Function Calling Agent：能调用一个 **Mock 搜索工具**，无需 API Key 即可看懂机制。
- 产出：可离线运行的循环 demo（`--mock`）。

### Stage 2 · 中级能力接入（第 7–22 节）
- **Tool Registry** 统一管理多个工具，告别 `if-else` 路由。
- **MCP** 接入真实数据源（把自有工具暴露给任意 Agent）。
- **RAG** 读取产品文档 / 历史评测，让 Agent 像专家一样引用资料。
- **Agent Memory** 跨轮记忆用户偏好与研究上下文。
- **LangGraph** 编排复杂流程，支持 Checkpoint 与 Human-in-the-Loop。
- 第 21 节产出**项目骨架**，第 22 节**中级复盘验收**。

### Stage 3 · 高级闭环与上线（第 23–36 节）
- 综合项目四连击：架构设计 → 核心开发 → 能力增强 → 评测优化 → 复盘（第 30–34 节）。
- 叠加**可靠性 / 安全 / 可观测性 / 成本优化**（第 23–28 节）。
- 接入**评测体系**（第 20、33 节），用真实用例量化「做对了几题」。
- **生产化部署与监控**（第 36 节），从笔记本 demo 走向可服务的系统。

## 如何运行

随课程逐步补充。约定：**所有脚本统一支持 `--mock` 离线运行**，先看机制、再接真实模型。
真实模型调用需设置 `OPENAI_API_KEY`（或 OpenAI 兼容厂商的 `BASE_URL` / `MODEL`）。

## 与课程的关系

- `dayNN-*`：单点能力的**最小可运行示例**（教学用）。
- `projects/saas-competitor-agent/`：把这些能力**组合成真实系统**（实战用）。
- 建议学习顺序：先跑通对应 `dayNN` 的示例，再回到本项目把它「接进去」。
